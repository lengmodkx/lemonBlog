## Project Overview

Lemon Blog is a modern, static blog platform built with Next.js App Router and Tailwind CSS. It features:

- **Static Site Generation**: All blog posts are generated as static pages at build time
- **Markdown Content**: Articles are stored as Markdown files in `/content/articles`
- **Syntax Highlighting**: Code blocks with Prism.js syntax highlighting (rehype-prism-plus)
- **Dark Mode**: Full dark/light mode support with system preference detection
- **Responsive Design**: Mobile-first design with Tailwind CSS
- **SEO Optimized**: Built-in metadata and OpenGraph support
- **Image Service**: Unified image service supporting Unsplash, GIPHY, and Storyset
- **Cover Images**: Automatic cover image extraction from article content

## Project Architecture

### Key Architectural Patterns

**Image Path Resolution**: The blog supports two image storage patterns:
1. Per-article: `content/articles/{slug}/img/*` → `/articles/{slug}/img/*`
2. Shared: `content/articles/img/*` → `/articles/img/*`

Relative image paths in markdown (e.g., `img/photo.jpg`) are automatically converted to absolute paths during build time via `fixImagePaths()` in `src/lib/posts.ts`.

**Image Service Architecture** (`src/lib/images/`):
- `index.ts`: Unified `imageService` class with caching
- `unsplash.ts`: Unsplash photo integration
- `giphy.ts`: GIPHY GIF integration
- `storyset.ts`: Storyset illustration integration
- All services follow a consistent pattern: search, random, and optimized URL generation

**Cover Image Extraction**: The first image in markdown content is automatically extracted as the cover image. This supports both markdown syntax `![alt](url)` and HTML `<img>` tags. The extracted image is removed from the content to avoid duplication.

## Content Management

### Adding New Blog Posts

1. Create a new `.md` file in `/content/articles/`
2. Include required frontmatter:
   ```yaml
   ---
   title: "Article Title"
   date: "YYYY-MM-DD"
   description: "Brief description"
   author: "Author Name"
   tags: ["tag1", "tag2"]
   ---
   ```
3. Add images to either `content/articles/{slug}/img/` (per-article) or `content/articles/img/` (shared)
4. Reference images in markdown as `img/filename.jpg` - paths will be auto-converted
5. The first image in content becomes the cover image automatically

### Frontmatter Fields

- **title**: Required. The article title
- **date**: Required. Publication date (YYYY-MM-DD format)
- **description**: Required. Brief description for SEO and previews
- **author**: Required. Author name (defaults to "Anonymous")
- **tags**: Optional. Array of string tags for categorization (also used for image matching)

### Travel Gallery (`/travel`)

The travel gallery shows photos in two views: an interactive China map (ECharts, zoom/drag enabled) and a date timeline. Clicking a city dot or a province on the map opens that location's photos.

Data source: `content/travel/photos.json` (`{ trips: [], photos: [] }`), read by `src/lib/travel.ts`. Per photo: `src` (required), `date`, `city`, `province` (required; must match map region names like `浙江省` / `西藏自治区` / `北京市`), optional `id`, `thumb`, `coords` (`[lng, lat]`), `caption`, `trip`, `group`. See `content/travel/README.md` for the full schema.

- **Burst / same-scene collapsing**: `src/lib/travel-burst.ts` collapses high-speed bursts (consecutive camera frame numbers in `id`, e.g. `dkx05241`) and explicit `group` stacks into one representative photo per stack; hidden frames stay browsable in the lightbox (`burst` array on the representative). Use `countPhotos()` from that module wherever shot counts are displayed.

- **City coordinates**: `src/data/city-coords.ts` — photos only need a city name; unknown cities can carry explicit `coords`.
- **Map data**: `src/data/china-geo.json` (35 provinces incl. 南海诸岛), generated from DataV boundaries via `node scripts/simplify-china-geo.mjs <source.json>`.
- **Upload photos to RustFS**: configure `RUSTFS_*` in `.env.local` (see `.env.local.example`; `.env.local` is git-ignored and never pushed to GitHub), then `node scripts/upload-to-rustfs.js <dir> --prefix travel/2025-04-hangzhou`. The RustFS public image host itself is not a secret: add it to `PUBLIC_IMAGE_HOSTS` in `next.config.ts` so GitHub/Vercel builds need no env config.
- Components: `src/components/travel/` (`TravelGallery`, `ChinaMap`, `TimelineView`, `PhotoGrid`, `PhotoLightbox`). The map is loaded client-side only (`dynamic` + `ssr: false`); theme changes (dark mode) re-render map colors.

### Adding New Thoughts

Short thoughts/ideas live as individual Markdown files in `content/thoughts/` and are rendered on the `/thoughts` page (timeline style, newest first). Each thought also has its own detail page at `/thoughts/{slug}`.

1. Create a new file `content/thoughts/YYYY-MM-DD.md` (or `YYYY-MM-DD-some-title.md` to disambiguate). The filename (without `.md`) becomes the slug / URL.
2. Use frontmatter for metadata and the rest as plain Markdown:
   ```markdown
   ---
   date: 2026-07-31
   title: 独立判断的代价    # optional
   tags: [随笔, 思辨]       # optional
   ---

   第一段…

   第二段（段间空一行即可）…
   ```
3. Both the list page and the detail page render the body through the same Markdown pipeline (`remark` + `remark-gfm`), so list and detail stay in sync. The list page shows up to 10 thoughts per page with URL pagination (`/thoughts?page=2`); sort and excerpt are derived automatically.

Supported Markdown features: paragraphs, headings, lists, blockquotes, fenced code, inline emphasis, links, images, and raw HTML (passes through). Plain paragraph text (the common case) just needs blank lines between paragraphs.

### Image Handling

**For article images** (displayed in content):
- Place in `content/articles/{slug}/img/` or `content/articles/img/`
- Reference as `![alt](img/filename.jpg)` in markdown
- Paths are automatically converted to `/articles/...` at build time

**For cover images**:
- First image in markdown is auto-extracted as cover
- Supports `![alt](url)` and `<img src="url">` syntax
- Removed from content after extraction to avoid duplication
- Can be overridden via `coverImage` property in Post type

**For BannerImage component**:
- Accepts `customImage` prop to override automatic selection
- Falls back to Unsplash/GIPHY/Storyset based on tags if no custom image
- Supports `preferredSource` prop ('unsplash', 'giphy', 'storyset')
